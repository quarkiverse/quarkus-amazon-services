NOTE: The {service-name-uppercase} extension is based on https://docs.aws.amazon.com/sdk-for-java/v2/developer-guide/welcome.html[AWS Java SDK 2.x].
It's a major rewrite of the 1.x code base that offers two programming models (Blocking & Async).

The Quarkus extension supports two programming models:

* Blocking access using URL Connection HTTP client (by default), the Apache HTTP Client or the AWS CRT-based HTTP client
* https://docs.aws.amazon.com/sdk-for-java/v2/developer-guide/basics-async.html[Asynchronous programming] based on JDK's `CompletableFuture` objects and the Netty HTTP client or the AWS CRT-based HTTP client

To complete this guide, you need:

* JDK {jdk-version} installed with `JAVA_HOME` configured appropriately
* an IDE
* Apache Maven {maven-version}
* https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-install.html[AWS Command Line Interface]
* An AWS Account to access the {service-name-uppercase} service

=== Provision {service-name-uppercase} locally manually

You can also set up a local version of {service-name-uppercase} manually, first start a {aws-stack-name} container:

ifeval::["{aws-stack}" == "floci"]
[source,bash,subs="verbatim,attributes"]
----
docker run --rm --name floci --publish 4566:4566 -d floci/floci:latest
----
This starts a Floci instance that is accessible on port `4566`. Floci exposes all the services it emulates on this single endpoint.
endif::[]
ifeval::["{aws-stack}" == "localstack"]
[source,bash,subs="verbatim,attributes"]
----
docker run --rm --name localstack --publish 4566:4566 -e SERVICES={localstack-service} -e START_WEB=0 -d localstack/localstack:4.13
----
This starts a {service-name-uppercase} instance that is accessible on port `4566`.
endif::[]
ifeval::["{aws-stack}" == "moto"]
[source,bash,subs="verbatim,attributes"]
----
docker run --rm --name moto --publish 5000:5000 -d motoserver/moto:latest
----
This starts a {service-name-uppercase} mock instance that is accessible on port `5000`.
endif::[]

Create an AWS profile for your local instance using AWS CLI:
[source,shell,subs="verbatim,attributes"]
----
$ aws configure --profile {aws-stack}
AWS Access Key ID [None]: test-key
AWS Secret Access Key [None]: test-secret
Default region name [None]: us-east-1
Default output format [None]:
----
endif::[]

== Creating the Maven project

First, we need a new project. Create a new project with the following command:

[source,bash,subs=attributes+]
----
mvn io.quarkus.platform:quarkus-maven-plugin:{quarkus-version}:create \
    -DprojectGroupId=org.acme \
    -DprojectArtifactId=amazon-{extension-name}-quickstart \
    -DclassName="org.acme.{java-package}.{main-class}" \
    -Dpath="{main-path}" \
    -Dextensions="resteasy-reactive-jackson,amazon-{extension-name}"
cd amazon-{extension-name}-quickstart
----

This command generates a Maven structure importing the RESTEasy Reactive/JAX-RS and Amazon {service-name-uppercase} Client extensions.
After this, the `amazon-{extension-name}` extension has been added to your `pom.xml` as well as the Mutiny support for RESTEasy.

== Using the {service-name-uppercase} client

The extension exposes the synchronous and asynchronous {service-name-uppercase} clients of the AWS SDK as CDI beans, so you only need to inject them.

Edit the `org.acme.{java-package}.{main-class}` REST resource created by the previous command to inject the synchronous client:

[source,java,subs="attributes+"]
----
package org.acme.{java-package};

import jakarta.inject.Inject;
import jakarta.ws.rs.Path;

import software.amazon.awssdk.services.{sdk-package}.{service-class-name}Client;

@Path("{main-path}")
public class {main-class} {

    @Inject
    {service-class-name}Client client;

    // Call the client from your endpoints
}
----

To inject several clients with different configurations, refer to the xref:common-features.adoc[named clients] support.
endif::[]

== Configuring {service-name-uppercase} clients

Both {service-name-uppercase} clients (sync and async) are configurable via the `application.properties` file that can be provided in the `src/main/resources` directory.
Additionally, you need to add to the classpath a proper implementation of the sync client. By default, the extension uses the URL connection HTTP client, so
you need to add a URL connection client dependency to the `pom.xml` file:

[source,xml]
----
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>url-connection-client</artifactId>
</dependency>
----

If you want to use the Apache HTTP client instead, configure it as follows:
[source,properties,subs=attributes]
----
quarkus.{service-name}.sync-client.type=apache
----

And add the following dependency to the application `pom.xml`:
[source,xml]
----
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>apache-client</artifactId>
</dependency>
----

If you want to use the AWS CRT-based HTTP client instead, configure it as follows:
[source,properties,subs=attributes]
----
quarkus.{service-name}.sync-client.type=aws-crt
----

And add the following dependency to the application `pom.xml`:
[source,xml]
----
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>aws-crt-client</artifactId>
</dependency>
----

If you're going to use a local {service-name-uppercase} instance (for example {aws-stack-name}), configure it as follows:

[source,properties,subs="attributes+"]
----
quarkus.{service-name}.endpoint-override=http://localhost:{aws-stack-port} <1>

quarkus.{service-name}.aws.region=us-east-1 <2>
quarkus.{service-name}.aws.credentials.type=static <3>
quarkus.{service-name}.aws.credentials.static-provider.access-key-id=test-key
quarkus.{service-name}.aws.credentials.static-provider.secret-access-key=test-secret
----
ifdef::has-devservices[]
<1> Override the {service-name-uppercase} client to use {aws-stack-name} instead of the actual AWS service. When it is set, Dev Services does not start a local stack for {service-name-uppercase}.
endif::[]
ifndef::has-devservices[]
<1> Override the {service-name-uppercase} client to use {aws-stack-name} instead of the actual AWS service
endif::[]
<2> {aws-stack-name} defaults to `us-east-1`
<3> The `static` credentials provider lets you set the `access-key-id` and `secret-access-key` directly

If you want to work with an AWS account, you can simply remove or comment out all Amazon {service-name-uppercase} related properties. By default, the {service-name-uppercase} client extension will use the `default` credentials provider chain that looks for credentials in this order:

* Java System Properties - `aws.accessKeyId` and `aws.secretAccessKey`
* Environment Variables - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`
* Credential profiles file at the default location (`~/.aws/credentials`) shared by all AWS SDKs and the AWS CLI
* Credentials delivered through the Amazon ECS if the `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` environment variable is set and the security manager has permission to access the variable,
* Instance profile credentials delivered through the Amazon EC2 metadata service

And the region from your AWS CLI profile will be used.

=== Going asynchronous

Thanks to the AWS SDK v2.x used by the Quarkus extension, you can use the asynchronous programming model out of the box.

include::../_extras/{docname}-async-usage.adoc[opts=optional]

ifndef::custom-async-usage[]
Create a `org.acme.{java-package}.Quarkus{service-class-name}AsyncResource` REST resource that will be similar to our `{main-class}` but using the asynchronous client:

[source,java,subs="attributes+"]
----
package org.acme.{java-package};

import jakarta.inject.Inject;
import jakarta.ws.rs.Path;

import software.amazon.awssdk.services.{sdk-package}.{service-class-name}AsyncClient;

@Path("/async")
public class Quarkus{service-class-name}AsyncResource {

    @Inject
    {service-class-name}AsyncClient client;

    // Call the client from your endpoints
}
----

The methods of the asynchronous client return `CompletableFuture` objects, which you can turn into Mutiny `Uni` instances with `Uni.createFrom().completionStage(...)`.
endif::[]

To enable the asynchronous client, you also need to add the Netty HTTP client dependency to the `pom.xml`:

[source,xml]
----
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>netty-nio-client</artifactId>
</dependency>
----

If you want to use the AWS CRT-based HTTP client instead, configure it as follows:
[source,properties,subs=attributes]
----
quarkus.{service-name}.async-client.type=aws-crt
----

And add the following dependency to the application `pom.xml`:
[source,xml]
----
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>aws-crt-client</artifactId>
</dependency>
----
