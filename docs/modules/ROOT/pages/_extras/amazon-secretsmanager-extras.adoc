== Using AWS Secrets Manager as a Quarkus Config Source

In addition to injecting `SecretsManagerClient` / `SecretsManagerAsyncClient`, you can use AWS Secrets Manager as a configuration source.
When enabled, Quarkus will fetch secret values at startup and expose them as configuration properties.

=== Enable the Config Source

Enable the config source by setting:

[source,properties]
----
quarkus.secretsmanager.config.enabled=true
----

=== Map configuration properties to secret names

The most common approach is to map application configuration keys to Secrets Manager secret names:

[source,properties]
----
quarkus.secretsmanager.config.enabled=true

# Map a config property name -> AWS Secrets Manager secret name
quarkus.secretsmanager.config.secrets."my.service.password"=prod/my-service/password
quarkus.secretsmanager.config.secrets."my.service.api-key"=prod/my-service/api-key
----

With this mapping in place, you can use the values like any other Quarkus configuration value (for example via `@ConfigProperty(name="my.service.password")`).

The mapped value can be a secret name or ARN. Only the mapped secrets are fetched (with `GetSecretValue`), so the `secretsmanager:ListSecrets` permission is not required. Several properties can map to the same secret.

=== Expose secrets directly by name (no mapping)

If you leave the mapping empty, the config source will load all accessible secrets and expose them using the secret name as the configuration property name.
For example, a secret named `prod/my-service/password` becomes a configuration property with the same name.

NOTE: Loading all secrets can be expensive and may require additional IAM permissions (because it lists secrets and then fetches each value). Prefer explicit mappings for production use.

=== JSON Secrets Parsing

Secret values that are JSON objects or arrays are automatically detected and flattened into individual configuration properties. This allows complex configuration structures to be managed as a single secret.

==== JSON Flattening Examples

When a secret contains a JSON object like `{"host":"localhost","port":5432}`, it is automatically flattened:

[source,properties]
----
quarkus.secretsmanager.config.enabled=true
quarkus.secretsmanager.config.secrets."db.config"=my-db-secret
----

If `my-db-secret` contains:
[source,json]
----
{"host":"localhost","port":5432,"user":"admin"}
----

It exposes these configuration properties:
[source]
----
db.config.host = localhost
db.config.port = 5432
db.config.user = admin
----

Nested JSON objects are flattened with dot notation:

[source,json]
----
{
  "connection": {
    "host": "db.example.com",
    "port": 5432
  },
  "pool": {
    "size": 10
  }
}
----

Exposes:
[source]
----
db.config.connection.host = db.example.com
db.config.connection.port = 5432
db.config.pool.size = 10
----

JSON arrays use index notation:

[source,json]
----
[
  {"name": "server1", "ip": "1.1.1.1"},
  {"name": "server2", "ip": "2.2.2.2"}
]
----

Exposes:
[source]
----
db.config[0].name = server1
db.config[0].ip = 1.1.1.1
db.config[1].name = server2
db.config[1].ip = 2.2.2.2
----

If JSON parsing fails or the value is empty JSON (`{}` or `[]`), the raw string value is used as a fallback.

==== Mapping with JSON Secrets

When using property name to secret name mappings, JSON secrets are flattened using the mapped property name as the prefix:

[source,properties]
----
quarkus.secretsmanager.config.enabled=true
quarkus.secretsmanager.config.secrets."app.database.host"=prod-db-config
quarkus.secretsmanager.config.secrets."app.cache.host"=prod-cache-config
----

If `prod-db-config` contains `{"host":"db.prod.aws","port":5432}`, it exposes:
[source]
----
app.database.host.host = db.prod.aws
app.database.host.port = 5432
----

This allows you to organize multiple JSON secrets under different configuration hierarchies.

=== Credentials, region, and endpoint

The config source uses the same Secrets Manager client configuration as the rest of the extension (credentials provider chain, region, and optional endpoint override).
This is particularly useful for a local stack such as Floci:

[source,properties]
----
quarkus.secretsmanager.endpoint-override=http://localhost:4566
quarkus.secretsmanager.aws.region=us-east-1
quarkus.secretsmanager.aws.credentials.type=static
quarkus.secretsmanager.aws.credentials.static-provider.access-key-id=test-key
quarkus.secretsmanager.aws.credentials.static-provider.secret-access-key=test-secret

quarkus.secretsmanager.config.enabled=true
quarkus.secretsmanager.config.secrets."secret.name"=my-local-secret
----

=== Notes and limitations

- The values are loaded once at startup (the config source does not poll for updates).
- If a secret cannot be fetched (access denied, deleted, throttling, etc.), Quarkus will log the error and continue loading other secrets.
- JSON detection is automatic based on content (value starts with `{` or `[`). No configuration is needed.
- Empty JSON objects or arrays (`{}` or `[]`) are treated as raw strings rather than being expanded.
- Invalid JSON values are gracefully handled by exposing the raw string value.
