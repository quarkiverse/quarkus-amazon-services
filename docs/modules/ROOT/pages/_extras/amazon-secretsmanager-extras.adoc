[[configuration]]
== Using AWS Secrets Manager as a Quarkus Config Source

Load application properties from explicit Secrets Manager secrets. See xref:common-config.adoc[Configuration from AWS]
to compare providers, read properties in your application and configure AWS access.
This ConfigSource loads values at startup and can poll for updates.

=== Map configuration properties to secret names

Create plain-text secrets `prod/my-service/password` and `prod/my-service/api-key` with the values your application needs:

[source,properties]
----
quarkus.secretsmanager.config.enabled=true
quarkus.secretsmanager.config.secrets."my.service.password"=prod/my-service/password
quarkus.secretsmanager.config.secrets."my.service.api-key"=prod/my-service/api-key
----

Reading `my.service.password` or `my.service.api-key` now returns the corresponding secret text.
The target property name becomes a prefix when the secret contains a document. The selection can be a secret name or ARN
(prefer full ARNs). Only explicit selections are fetched; several targets can select the same secret.

[IMPORTANT]
====
An empty selection no longer lists every secret in the account. Specify `entries` or `secrets` explicitly.
Without a selection, startup fails by default; `quarkus.secretsmanager.config.fail-on-missing-config=false` skips this source.
Default reads use `GetSecretValue`: neither `ListSecrets` nor `BatchGetSecretValue` permission is required.
====

=== Named entries

[source,properties]
----
quarkus.secretsmanager.config.enabled=true
quarkus.secretsmanager.config.entries.database.secret-id=prod/my-service/db
quarkus.secretsmanager.config.entries.database.prefix=db
quarkus.secretsmanager.config.entries.database.format=json
----

The name `database` identifies the entry, not its prefix. Named entries and legacy `secrets."property"=secret-id` mappings
can coexist. `quarkus.secretsmanager.config.format` is their default format; each entry can override it.

=== Refresh secret values

Polling is off by default. To read the selected secrets again after startup:

[source,properties]
----
quarkus.secretsmanager.config.update-interval=30S
----

After changing a secret and a successful refresh, xref:common-config.adoc#dynamic-reads[dynamic lookups] return its new value.
A failed refresh keeps the previous values. Each refresh makes AWS requests for the selected secrets and may incur charges.

[[_json_secrets_parsing]]
=== Read fields from a JSON secret

A *Key/value* secret created in the AWS console, or managed by Amazon RDS, is a JSON object. Mapping
`{"username":"app_user","password":"database-password"}` to prefix `db` exposes `db.username` and `db.password`, *not* `db`.
For nested documents, arrays, scalars and raw fallback, see xref:common-config.adoc#formats[Formats, prefixes and property names].
`SecretBinary` must contain valid UTF-8 text; arbitrary binary must be read directly with the SDK.

=== Optional batch retrieval

[source,properties]
----
quarkus.secretsmanager.config.batch-retrieval=true
----

Enable this option when you want to retrieve selected secrets in groups of up to 20 instead of individual reads.
It is off by default and applies even when only one secret is selected. Use consistent names/ARNs to avoid redundant reads;
batching does not discover additional secrets or enable polling by itself.

Grant `secretsmanager:BatchGetSecretValue` in addition to per-secret `secretsmanager:GetSecretValue` and appropriate
KMS decrypt permissions. `ListSecrets` is not required. Check IAM/resource and VPC endpoint policies when enabling the flag.
Denied or unsupported batch operations do not fall back to individual reads; disable the flag to use `GetSecretValue`.
If any selected secret fails to load, the xref:common-config.adoc#failure-policy[startup failure policy] applies.
No transaction, latency or billing saving is guaranteed.
Expressions still use `GetSecretValue`.

=== Resolve individual secrets with expressions

[source,properties]
----
myapp.api-key=${sm::prod/api-key}
myapp.database.password=${sm::prod/database#/password}
quarkus.secretsmanager.expression.cache-ttl=5M
----

If `prod/api-key` contains `example-key`, `myapp.api-key` returns `example-key`. The JSON example reads the `password`
field of `prod/database`. Both use the current (`AWSCURRENT`) value.
Grant `secretsmanager:GetSecretValue` and appropriate KMS decrypt permission; neither `ListSecrets` nor
`BatchGetSecretValue` is required. `SecretBinary` must contain valid UTF-8.
See xref:common-config.adoc#expressions[individual-value examples] for JSON Pointer syntax, caching and failures;
`config.enabled` is not required.
