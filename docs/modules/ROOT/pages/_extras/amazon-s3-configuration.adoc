==== Create the S3 bucket

Set the name of the S3 bucket used by the application:

[source,properties]
----
bucket.name=quarkus.s3.quickstart
----

Floci works with the default addressing style of the S3 client, so a manual local instance needs no extra property.
If your local stack does not support the virtual-hosted-style addressing of the S3 client, enable path-style access:

[source,properties]
----
quarkus.s3.path-style-access=true
----

.With Dev Services
Let Dev Services create the bucket on startup:

[source,properties]
----
quarkus.s3.devservices.buckets=${bucket.name}
----

.On a manually started Floci
Create the bucket using the AWS CLI of the Floci container:

[source,bash,subs="verbatim,attributes"]
----
docker exec floci aws s3 mb s3://quarkus.s3.quickstart
----

.On your AWS account
Create the bucket with your own AWS CLI:

[source,bash,subs="verbatim,attributes"]
----
aws s3 mb s3://quarkus.s3.quickstart
----

=== Creating a frontend

Now let's add a simple web page to interact with our `S3SyncClientResource`.
Quarkus automatically serves static resources located under the `META-INF/resources` directory.
In the `src/main/resources/META-INF/resources` directory, add a `s3.html` file with the content from this {quickstarts-blob-url}/amazon-s3-quickstart/src/main/resources/META-INF/resources/s3.html[s3.html] file in it.
