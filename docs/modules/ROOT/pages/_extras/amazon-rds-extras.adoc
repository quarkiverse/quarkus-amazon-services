== IAM database authentication for your datasource

With https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.IAMDBAuth.html[IAM database authentication], your application logs in to an RDS PostgreSQL, MySQL or MariaDB database with a token signed with its AWS credentials, instead of a password.
There is no database password to store, inject or rotate: the AWS credentials of the application, and its IAM permissions, decide who can connect.

The extension provides a Quarkus credentials provider, named `rds-credentials-provider`, that generates this token for your datasource.

=== Prepare the database

On AWS, IAM database authentication requires:

* IAM database authentication enabled on the DB instance or cluster
* an IAM policy, attached to the identity of the application, that allows `rds-db:connect` on `arn:aws:rds-db:<region>:<account-id>:dbuser:<DbiResourceId>/<db-user>`
* a database user that authenticates with IAM:
** PostgreSQL: `CREATE ROLE app_user LOGIN; GRANT rds_iam TO app_user;`
** MySQL and MariaDB: `CREATE USER app_user IDENTIFIED WITH AWSAuthenticationPlugin AS 'RDS';`

=== Minimal setup with the default client

For a PostgreSQL datasource using IAM authentication, add these dependencies to your application `pom.xml`:

[source,xml]
----
<dependency>
    <groupId>io.quarkiverse.amazonservices</groupId>
    <artifactId>quarkus-amazon-rds</artifactId>
</dependency>
<dependency>
    <groupId>io.quarkus</groupId>
    <artifactId>quarkus-jdbc-postgresql</artifactId>
</dependency>
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>url-connection-client</artifactId>
</dependency>
----

The URL connection HTTP client is the default, so its dependency is sufficient; no `quarkus.rds.sync-client.type` setting is needed.
The extension supplies the synchronous RDS client internally, even when your application only uses JDBC.
See <<Configuring {service-name-uppercase} clients>> for other HTTP client dependencies and their corresponding type settings.

Supply AWS credentials through the default AWS SDK credentials provider chain, for example through a workload IAM role or an AWS profile.
Supply the database's region through the default region provider chain, for example with `AWS_REGION=us-east-1` or the selected AWS profile's `region`.
You can also set `quarkus.rds.aws.region` and `quarkus.rds.aws.credentials.*` explicitly as described in <<Configuring {service-name-uppercase} clients>>.

With the database prepared as described above, the following `application.properties` configures the provider and datasource using the default client:

[source,properties]
----
quarkus.rds.credentials-provider.mydatabase.username=app_user <1>
quarkus.rds.credentials-provider.mydatabase.hostname=mydb.123456789012.us-east-1.rds.amazonaws.com
quarkus.rds.credentials-provider.mydatabase.port=5432

quarkus.datasource.db-kind=postgresql <2>
quarkus.datasource.jdbc.url=jdbc:postgresql://mydb.123456789012.us-east-1.rds.amazonaws.com:5432/mydb
quarkus.datasource.credentials-provider=mydatabase <3>
quarkus.datasource.credentials-provider-name=rds-credentials-provider <4>
----
<1> The token is valid only for this database user, host and port, and for the region of the client: use the host and port of the JDBC URL.
<2> The only property in this example fixed at build time. It can be omitted when PostgreSQL is the only available database kind.
<3> The name of the provider defined above. The provider returns both the username and the token, so you do not need `quarkus.datasource.username` or `quarkus.datasource.password`.
<4> The CDI name of the credentials provider bean. It is required when your application has another credentials provider, for example the Vault one.

All other properties in this example, as well as the client's region and credentials, can be supplied at runtime through environment variables or other configuration sources.
The credentials provider can therefore be configured when the application is deployed, without being configured locally at build time.

MySQL and MariaDB send the token in clear text, so the connection must use SSL. PostgreSQL uses SSL when the server offers it, which RDS does.

=== Use a named client

If database authentication needs a different region or AWS credentials, select a xref:common-features.adoc#_named_clients[named client] at build time:

[source,properties]
----
quarkus.rds.credentials-provider.mydatabase.name=myrdsclientforiam
----

The named client's region and credentials can be configured at runtime, as can the provider's username, hostname and port.
Without a client name configured at build time, the provider uses the default client.

=== Token lifetime

A token is valid for 15 minutes, and only to open a connection: a connection that is already open stays open when its token expires.
The datasource calls the credentials provider each time it opens a new connection, so each new connection gets a fresh token.
See the https://quarkus.io/guides/credentials-provider#time-limited-credentials[time-limited credentials] section of the Quarkus credentials provider guide.
