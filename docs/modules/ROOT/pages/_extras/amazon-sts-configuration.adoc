==== Create the role to assume

The application of this guide assumes an IAM role named `quarkus-role`, that the account can assume.

.With Dev Services
To create the `quarkus-role` role automatically at startup, provide init scripts.
Dev Services automatically selects the `latest-compat` image with the AWS CLI unless `image-name` is explicitly configured:

[source,properties]
----
quarkus.aws.devservices.floci.init-scripts-classpath=floci-init
quarkus.aws.devservices.floci.init-completion-msg=#### Init completed
----

Create `src/main/resources/floci-init/01_create_role.sh`:

[source,bash]
----
#!/bin/bash
aws iam create-role --role-name quarkus-role \
    --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::000000000000:root"},"Action":"sts:AssumeRole"}]}'
----

Then create `src/main/resources/floci-init/99_completed.sh`, which prints the message Dev Services waits for:

[source,bash]
----
#!/bin/bash
echo "#### Init completed"
----

Dev Services looks up the scripts in the classpath of the application, so keep them in `src/main/resources`: in dev mode, `src/test/resources` is not part of the classpath.
See xref:dev-services.adoc[Dev Services for Amazon Services] for the init script details.

.On a manually started Floci
Create the role using the AWS CLI of the Floci container:

[source,bash,subs="verbatim,attributes"]
----
docker exec floci aws iam create-role --role-name quarkus-role \
    --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::000000000000:root"},"Action":"sts:AssumeRole"}]}'
----

.On your AWS account
Create the same role with your own AWS CLI, replacing `<account-id>` with the ID of your account:

[source,bash,subs="verbatim,attributes"]
----
aws iam create-role --role-name quarkus-role \
    --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::<account-id>:root"},"Action":"sts:AssumeRole"}]}'
----

Your credentials also need the permission to call `sts:AssumeRole` on this role.
