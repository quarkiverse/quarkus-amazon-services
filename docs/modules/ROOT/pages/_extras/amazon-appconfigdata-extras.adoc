[[configuration]]
== Using AWS AppConfig Data as a Quarkus Config Source

Load application properties from a deployed AppConfig profile. See xref:common-config.adoc[Configuration from AWS]
to compare providers, read properties in your application and configure AWS access.

=== Application, environment, and configuration profile

Deploy a configuration such as `{"greeting":"hello"}`, then select its application, environment and profile:

[source,properties]
----
quarkus.appconfigdata.config.enabled=true
quarkus.appconfigdata.config.application=my-application
quarkus.appconfigdata.config.environment=production
quarkus.appconfigdata.config.configuration-profile=my-profile
----

Reading the `greeting` property now returns `hello`. Use IDs or names for the selection. Grant `appconfig:StartConfigurationSession` and
`appconfig:GetLatestConfiguration` for the selected configurations, plus KMS decrypt permission where required.
Configure all three identifiers; missing identifiers prevent startup by default.

=== Named profiles and prefixes

[source,properties]
----
quarkus.appconfigdata.config.enabled=true
quarkus.appconfigdata.config.entries.main.application=my-application
quarkus.appconfigdata.config.entries.main.environment=production
quarkus.appconfigdata.config.entries.main.configuration-profile=my-profile
quarkus.appconfigdata.config.entries.main.prefix=myapp
quarkus.appconfigdata.config.entries.main.format=auto
quarkus.appconfigdata.config.entries.main.required-minimum-poll-interval-in-seconds=15
----

For `{"feature":{"enabled":true}}`, the exposed key is `myapp.feature.enabled`; `main` is not a prefix.
Each entry inherits the source-wide format and session minimum unless overridden.
You can combine this with the application/environment/configuration-profile selection above; that selection remains
unprefixed. If you select the same profile more than once, the largest requested minimum polling interval applies.

=== Refresh deployed values

Polling is off by default. To check for updates with a requested delay of 30 seconds:

[source,properties]
----
quarkus.appconfigdata.config.update-interval=30S
quarkus.appconfigdata.config.required-minimum-poll-interval-in-seconds=15
----

The wait after each read is at least 30 seconds and may be longer if AWS requires it.
Without an explicit minimum, the minimum is 60 seconds. Accepted minimum values range from 15 to 86400 seconds;
`update-interval` must be at least one second to enable polling.

After deploying a changed profile, xref:common-config.adoc#dynamic-reads[dynamic lookups] return the new values once
a refresh succeeds. A failed read keeps the last valid values and later polling can recover automatically.
For `auto`/`json` configuration, deploying `{}` or `[]` removes that profile's properties after a successful refresh;
a whitespace-only properties document also clears its properties.

=== Formats and YAML migration

`quarkus.appconfigdata.config.format` defaults to `auto`: valid JSON objects/arrays take priority over Content-Type;
otherwise a YAML Content-Type selects YAML, and other content is read as Java properties. Without a YAML Content-Type,
nested YAML is not automatically detected. A named entry with a non-empty prefix also permits `raw` and non-null JSON scalars.
See xref:common-config.adoc#formats[Formats, prefixes and property names] for explicit formats and the YAML dependency.

[IMPORTANT]
====
YAML documents were previously read as Java properties. For `Content-Type: application/yaml`, this document now exposes
`feature.enabled=true` instead of the old separate `feature` (empty value) and `enabled` keys:

[source,yaml]
----
feature:
  enabled: true
----

Update consumers to use `feature.enabled` and install `io.quarkus:quarkus-config-yaml`, or set
`quarkus.appconfigdata.config.format=properties` to retain the old interpretation.
When YAML is selected but its extension is missing, decoding fails; there is no properties fallback.
====

=== Load a configuration in the local stack

AppConfig Data only serves configurations that are deployed: a hosted version alone is returned as an empty document.
To try the source with Dev Services, create and deploy a configuration with an
xref:dev-services.adoc#_init_scripts[init script], for example `src/test/resources/floci-init/01_setup_appconfigdata.sh`:

[source,bash]
----
#!/usr/bin/env bash
APPLICATION_ID=$(aws appconfig create-application --name my-application --query 'Id' --output text)
ENVIRONMENT_ID=$(aws appconfig create-environment --application-id "${APPLICATION_ID}" \
    --name production --query 'Id' --output text)
CONFIGURATION_PROFILE_ID=$(aws appconfig create-configuration-profile --application-id "${APPLICATION_ID}" \
    --name my-profile --location-uri hosted --type AWS.Freeform --query 'Id' --output text)

VERSION_NUMBER=$(aws appconfig create-hosted-configuration-version --application-id "${APPLICATION_ID}" \
    --configuration-profile-id "${CONFIGURATION_PROFILE_ID}" \
    --content "$(echo '{"greeting": "hello"}' | base64)" --content-type application/json \
    --query 'VersionNumber' --output text /dev/null)

DEPLOYMENT_STRATEGY_ID=$(aws appconfig create-deployment-strategy --name all-at-once \
    --deployment-duration-in-minutes 0 --growth-factor 100 --final-bake-time-in-minutes 0 \
    --replicate-to NONE --query 'Id' --output text)

aws appconfig start-deployment --application-id "${APPLICATION_ID}" --environment-id "${ENVIRONMENT_ID}" \
    --configuration-profile-id "${CONFIGURATION_PROFILE_ID}" --configuration-version "${VERSION_NUMBER}" \
    --deployment-strategy-id "${DEPLOYMENT_STRATEGY_ID}"

echo "#### Init completed"
----

Select the Floci image with the AWS CLI and wait for initialization before loading the source:

[source,properties]
----
quarkus.aws.devservices.floci.image-name=floci/floci:latest-compat
quarkus.aws.devservices.floci.init-scripts-folder=src/test/resources/floci-init
quarkus.aws.devservices.floci.init-completion-msg=#### Init completed

quarkus.appconfigdata.config.enabled=true
quarkus.appconfigdata.config.application=my-application
quarkus.appconfigdata.config.environment=production
quarkus.appconfigdata.config.configuration-profile=my-profile
----

The `greeting` property then resolves to `hello`.
