[[configuration]]
== Using AWS Systems Manager Parameter Store as a Quarkus Config Source

Load application properties from SSM parameters. See xref:common-config.adoc[Configuration from AWS] to compare
providers, read properties in your application and configure AWS access.

=== Load parameters by path or name

Create parameter `/myapp/prod/db/url` with value `jdbc:postgresql://database.example.com:5432/myapp`.
Enable the source and select its parent path:

[source,properties]
----
quarkus.ssm.config.enabled=true
quarkus.ssm.config.path=/myapp/prod/
----

The `db.url` property contains that JDBC URL. Nested parameters are included and SecureString values are decrypted by default;
use `recursive=false` or `with-decryption=false` under `quarkus.ssm.config` to change those settings.

To select only this parameter, replace `path` with an explicit name:

[source,properties]
----
quarkus.ssm.config.enabled=true
quarkus.ssm.config.names[0]=/myapp/prod/db/url
----

The property is then `myapp.prod.db.url`, because explicit selections retain the full name.
You can also combine paths and explicit names. Grant `ssm:GetParametersByPath` for path selections or
`ssm:GetParameters` for explicit names, plus appropriate KMS decrypt permissions for SecureString values.
An empty selection fails startup by default; `quarkus.ssm.config.fail-on-missing-config=false` skips the source instead.

=== Named paths and prefixes

[source,properties]
----
quarkus.ssm.config.enabled=true
quarkus.ssm.config.entries.database.path=/myapp/prod
quarkus.ssm.config.entries.database.prefix=myapp
quarkus.ssm.config.entries.database.format=auto
quarkus.ssm.config.entries.database.recursive=true

# Optional shorthand: prefix -> path, inheriting source-wide format/recursive settings
quarkus.ssm.config.path."shared"=/common/prod
----

`/myapp/prod/db/url` exposes `myapp.db.url`; the entry name `database` is not a prefix.
The scalar `path`, prefix shortcuts, named entries and explicit `names` can be combined.

=== How configuration keys are exposed

* Path selections use names relative to the loaded path: `/myapp/prod/db/url` loaded from `/myapp/prod` exposes `db.url`, plus any configured prefix.
* Explicit `names` use the full name: `/myapp/prod/url` exposes `myapp.prod.url`.
* `/` becomes `.`. For relative path naming only, complete index segments such as `_0_` become `[0]`: `/myapp/prod/servers/_0_/name` loaded from `/myapp/prod` exposes `servers[0].name`.
* Document values are decoded under that parameter key. For example, explicit name `/myapp/db` containing
  `{"connection":{"host":"db.example.com"}}` exposes `myapp.db.connection.host`.

For format behavior, including JSON arrays/scalars, empty documents and raw fallback, see
xref:common-config.adoc#formats[Formats, prefixes and property names].
`quarkus.ssm.config.format` supplies the default; `entries.<name>.format` overrides it.

[IMPORTANT]
====
Path-selected keys are now relative by default. For `/myapp/prod/db/url`, the key changes from `myapp.prod.db.url` to `db.url`.
To preserve full parameter names, set `quarkus.ssm.config.key-naming=full`.
Alternatively, replace `path=/myapp/prod` with `path."myapp.prod"=/myapp/prod` to restore the old prefix explicitly.
Explicit `names` are unaffected.
For values previously interpreted using equals-sign detection, explicitly set `quarkus.ssm.config.format=properties`.
====

[[path-polling]]
=== Optional polling

Set `quarkus.ssm.config.update-interval=30S` to re-fetch the selection after startup (default `PT0S`, minimum one second).
If a read fails or an explicitly selected name is missing, the previous values remain available.
Deleting a parameter under a selected path removes its properties after a successful complete refresh of that path.
Use xref:common-config.adoc#dynamic-reads[dynamic configuration lookups] to observe refreshed values.

=== Resolve individual parameters with expressions

[source,properties]
----
myapp.api-key=${ssm::/myapp/api-key}
# SSM version/label selectors and full ARNs are supported
myapp.previous-key=${ssm::/myapp/api-key:3}
myapp.database.password=${ssm::/myapp/database#/password}
quarkus.ssm.expression.cache-ttl=5M
----

If `/myapp/api-key` contains `example-key`, `myapp.api-key` returns `example-key`. The JSON example reads the `password`
field of `/myapp/database`. Grant `ssm:GetParameter` and the appropriate KMS decrypt permission; values are decrypted.
See xref:common-config.adoc#expressions[individual-value examples]
for JSON Pointer syntax, caching and failure behavior; `config.enabled` is not required.
